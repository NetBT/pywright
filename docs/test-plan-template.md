# AI 协作测试计划模板

将此文件复制到项目根目录 `specs/<业务域>-<流程>.md` 后填写。一个计划只覆盖一个可独立验收的用户流程。

```markdown
# <业务域>：<用户流程>

## 目标与风险

- 用户目标：<用户要完成什么>
- 覆盖范围：<本计划覆盖的边界>
- 不覆盖范围：<明确排除的内容>
- 主要风险：<数据丢失、支付失败、权限绕过、状态不同步等>

## 前置条件

- 环境：<default / uat / 其他环境名>
- 认证：<api_token / ui_login / reuse>
- 用户角色：<角色与必要权限>
- 初始数据：<已有实体、数据状态>
- 外部依赖：<真实依赖或 mock 契约>

## 测试数据与清理

| 名称 | 值或生成规则 | 归属 | 清理方式 |
| --- | --- | --- | --- |
| <例如待办标题> | <唯一且可追踪的值> | <测试用例> | <API 删除 / 自动过期> |

> 不得在计划、fixture、YAML 或生成提示中填写真实 token、密码或个人信息。

## 场景

### S1：<关键正向流程>

- 层级与标记：`smoke` + `ui` / `api` / `integration`
- 优先级：P0
- 前置条件：<本场景专属条件>
- 步骤：
  1. <用户可观察的操作>
  2. <用户可观察的操作>
- 预期结果：
  1. <可验证的页面或 API 结果>
  2. <可验证的持久化或业务后置状态>
- 自动化归属：<tests/ui/smoke/... 或其他目标路径>

### S2：<主要异常或边界流程>

- 层级与标记：`regression` + `ui` / `api`
- 优先级：P1
- 前置条件：<条件>
- 步骤：
  1. <操作>
- 预期结果：
  1. <错误提示、禁止提交、状态不变等>
- 自动化归属：<目标路径>

## 自动化设计

- 页面对象：<pages/ 下要新增或复用的类和方法>
- API 封装：<api/ 下要新增或复用的端点/Facade 方法>
- Fixture：<复用或新增的 fixture；避免测试间共享可变状态>
- 定位符契约：<role / label / text / test id；禁止依赖 CSS/XPath 结构路径>
- 断言：<web-first 断言或 API 契约断言；写明关键状态>
- 可观测性：<失败时需检查的 trace、网络、console、截图>

## AI 执行约束

- Planner 输入：<需求、seed test、相关页面/接口>
- Generator 输出：<计划对应的测试文件；测试中不得散写复杂定位符>
- Healer 边界：<仅允许建议最小修复，不得擅自修改产品逻辑、放宽断言、增加全局重试或提交敏感信息>
- 人工审阅项：<分层、marker、数据隔离、断言、删除无关生成代码>

## 验收与回归

- 最小验证命令：`uv run pytest <目标测试路径>`
- 关联回归命令：`uv run pytest -m <smoke / regression / integration>`
- 通过标准：<成功条件；包括无意外 flaky、无 console error 等>
- 已知限制：<环境、依赖、暂不自动化的原因>
```

## 使用准则

- `smoke` 只保留阻断发布的关键路径；异常、组合和完整边界场景放入 `regression`。
- UI 与 API 共同验证同一业务后置状态时使用 `integration`，不要为了标签而重复覆盖。
- 计划经人工审阅后，才允许 generator 产出测试代码；healer 的修改必须再次审阅并回归验证。
- 计划文件是可审计资产，应与对应需求、测试文件和缺陷链接保持可追溯关系。
